## CANDIDATE / CURRENT PUBLIC RESEARCH (2026-11-26)

Candidate: **Unity Build Automation (UBA), the managed Unity DevOps cloud service, under the Free plan**. It is not Unity Build Server.

Current official public pricing research (effective 2026-03-01) advertises, per organization/month:
- 200 Windows Minutes (Micro)
- 100 Linux Minutes (Micro)
- 100 Mac Minutes (Standard)
- 25 GB shared DevOps storage
- 100 GB egress

These figures are a public baseline only. The owner must read back the actual organization plan, entitlement, remaining quotas, billing state and usage in the Unity Dashboard. If the account shows different limits, use the dashboard values and stop until the zero-cost operating envelope is recalculated and approved.

Unity DevOps Free documentation warns that exceeding any free-plan service limit locks the DevOps project; without upgrade, access becomes read-only and cloud storage data may be deleted after 30 days. Unity sends usage warnings at 50%, 75% and 90%. Do not approach these thresholds.

UBA documentation states that its build target can run EditMode and PlayMode tests and mark the build failed when any test fails. A public GitHub repository can be connected without a token; if a token is required, the documented minimum classic-token scope for a public repo is `public_repo`, and enabling auto-build requires `write:repo_hook`. Do not create or enter a token before the explicit owner-approval/security gate below.

**License boundary:** Unity Editor Software Terms §2.5 prohibit using **Unity Build Server** with Unity Personal. Do not install/use on-prem Build Server, do not run a local headless Personal Editor, and do not infer Build Server rights from the Unity Personal license. UBA is a separate managed cloud service; verify the account's specific UBA entitlement and applicable terms before any activation. If the distinction or entitlement is ambiguous, stop and request official Unity clarification. This Work Order is not a legal opinion.
