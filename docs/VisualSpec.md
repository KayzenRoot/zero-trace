## Shared state wireframes and microcopy
All apps use header/context, body, status strip and clear action. Loading: skeleton plus Cancel where possible; Empty: explanation and relevant action; Ready: data + timestamp; Pending: receipt/reference, disabled duplicate submit, "Awaiting confirmation / Aguardando confirmação"; Failure/Error: reason + Retry or safe exit; Denied: lock, "Access denied / Acesso negado", authorized scope and no bypass; Recovery: last consistent snapshot/receipt, "Resume safely / Retomar com segurança"; Offline: explicit connection state and local-only actions; Read-only: reason and permitted views; Conflict: compare current vs attempted state, refresh and explicit resubmit. Never use success toast for pending financial transaction. No status by color alone. Concept visuals must show simulation context; real network/host commands and external targets are prohibited. Terminal examples use fictitious ZERO commands (e.g. world.status, case.list), not real attack or evasion recipes.
